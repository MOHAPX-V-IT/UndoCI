This record captures the existing implementation and supplied product brief. Repository-derived interpretations are labeled; they are not additional user approvals.

## Platform

web

The visual surface is a standalone browser report generated by a Python CLI. This platform value describes that report, not a hosted web service.

## Users

Derived from the CLI and report: developers investigating whether an older application release can still operate after a newer release writes data.

## Product Purpose

UndoCI rehearses baseline, upgrade and workload execution, rollback without restoring data, and verification. It records failures, searches action prefixes for a failure boundary, and reduces the workload to a reproducible scenario.

## Operating Context

The Python CLI creates local evidence artifacts: HTML, JSON, JUnit XML, a Markdown summary, and a replay manifest. The HTML report contains its own CSS and JavaScript and uses no external runtime assets or analytics.

## Capabilities and Constraints

- The report presents run status, confirmation, failure signature, boundary evidence, retained and removed actions, and a filterable rehearsal journal.
- Reduction preserves declared dependencies and action order. A 1-minimal result is not a globally shortest scenario.
- Matching signatures identify the same failing phase, step, and assertion; they do not establish identical root causes.
- Results cover configured versions, workloads, and assertions. They are not a universal rollback safety guarantee.

## Brand Commitments

The supplied brief establishes the UndoCI name and a black graphite/amber engineering direction. Existing assets are `docs/assets/undoci-banner.png` and `docs/assets/report-preview.png`. The report's durable visual rules are recorded separately in `DESIGN.md`.

## Evidence on Hand

Implementation: `src/undoci/templates/report.html` and `src/undoci/report.py`. Product workflow and runnable examples: `README.md` and `examples/`. The preview illustrates a demo regression; it is not customer evidence or a performance benchmark.

## Product Principles

Derived from the implemented workflow:

- Make findings inspectable through per-step evidence.
- Keep the workload and assertion scope visible beside conclusions.
- Preserve replayable, portable artifacts for developer investigation.
